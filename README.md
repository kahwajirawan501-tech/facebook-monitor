# Facebook Monitor (نسخة منظّمة)

بوت مراقبة صفحات/مجموعات/بروفايلات فيسبوك، يكتشف المنشورات الجديدة ويرسلها لـ Telegram،
مع OCR عبر Gemini Vision للصور بدون نص، وتخزين في Turso.

## بنية المشروع

```
config.py          كل إعدادات .env + تحميل selectors.json
selectors.json      selectors فيسبوك — عدّل هون فقط لما فيسبوك يغيّر HTML
logger_setup.py      إعداد logging موحّد (كونسول + ملف دوّار)
db.py                طبقة Turso (SQL محصور هون بالكامل)
telegram_client.py   إرسال المنشورات + تنبيهات النظام
ocr_engine.py         Gemini Vision OCR + تدوير المفاتيح عند 429/503
url_utils.py          تنظيف الروابط + استخراج معرّف المنشور
text_filters.py       فلترة الأسطر القمامة وعبارات الواجهة
post_parser.py         تحليل عنصر منشور واحد (يستخدم selectors.json)
monitor.py             مراقبة هدف واحد + HealthTracker لكشف انكسار الـ selectors
main.py                نقطة الدخول وربط كل شي
```

## أهم فرق عن النسخة القديمة

### 1. Selectors بملف منفصل (`selectors.json`)
كل الـ selectors (حاوية المنشور، أزرار الإغلاق، عبارات الواجهة...) صارت بملف JSON.
لما فيسبوك يغيّر بنية الصفحة، بتعدّل الملف وتعيد تشغيل السكربت — بدون لمس الكود.

`post_container` هو **قائمة** مش selector واحد:
```json
"post_container": [
  "div[role='feed'] > div",
  "div[role='article']",
  "div[data-pagelet*='FeedUnit']"
]
```
النظام بيجرب كل عنصر بالترتيب، وأول واحد يرجّع نتائج بيستخدمه. لو استخدم أي شي غير الأول،
بيسجّل تحذير بالـ log — هيك بتعرف بدري إنو الـ selector الأساسي بلش ينكسر، قبل ما يفشل كلياً.

### 2. تنبيه تلقائي عند احتمال انكسار الاستخراج
`HealthTracker` بـ `monitor.py` بيتتبع عدد الدورات المتتالية اللي ما لقت فيها أي منشور جديد
لكل هدف (مش أول دورة baseline). لو تجاوز عدد الدورات `EMPTY_CYCLES_ALERT_THRESHOLD`
(افتراضي 5)، بيرسل تنبيه Telegram صريح: "احتمال كبير إنو فيسبوك غيّر بنية الصفحة".
هيك ما بتضل تكتشف المشكلة صدفة بعد أسبوع.

### 3. Logging حقيقي بدل print
كل السجلات بتنكتب لملف دوّار بـ `logs/fb_monitor.log` (5MB × 5 نسخ احتياطية) بالإضافة
للكونسول، مع مستوى قابل للضبط عبر `LOG_LEVEL` بـ `.env`.

### 4. تقسيم لموديولات
كل مسؤولية بملف منفصل — أسهل بالاختبار، الصيانة، وفهم أي جزء يحتاج تعديل عند مشكلة معينة.

## التشغيل

```bash
cp .env.example .env
# عبّي القيم بـ .env
pip install -r requirements.txt
playwright install chromium
python main.py
```

## عند تغيّر بنية فيسبوك

1. راقب `logs/fb_monitor.log` أو تنبيهات Telegram لرسائل "⚠️ استخدم fallback selector"
   أو "لم يتم العثور على أي منشور جديد... خلال N دورات".
2. افتح صفحة فيسبوك يدوياً بالمتصفح، افحص الـ DOM الجديد (Inspect Element).
3. حدّث `selectors.json` بالـ selector الجديد (أضفه كأول عنصر بالقائمة، خلي القديم كـ fallback).
4. أعد تشغيل السكربت — ما في حاجة لتعديل أي كود Python.

## ملاحظة مهمة

فيسبوك بمنع scraping غير الرسمي بشروط الاستخدام (ToS) الخاصة فيه، خصوصاً لو بتستخدم
جلسة مستخدم حقيقي (`FB_AUTH_STATE_JSON`) بدل الوصول العام. هاد الملف بيحسّن جودة الكود
فقط ولا يغيّر من هالواقع — استخدم الأداة على مسؤوليتك، وفضّل ما أمكن الاعتماد على مصادر
رسمية (Graph API لصفحات تملكها، RSS، إلخ) لو متوفرة لحالتك.
